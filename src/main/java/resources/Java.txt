Marker Interface
In Java, a marker interface is an interface with no methods. Marker interfaces are used to indicate a special behavior
or capability that a class implementing the interface possesses. The presence of the marker interface on a class is
often used to trigger certain behavior or functionality.
Here are a few points about marker interfaces:
No Methods: Marker interfaces do not contain any methods. They simply act as a marker to signify that a class implementing the interface should be treated in a specific way.
Usage: Common use cases for marker interfaces include indicating that a class should be treated as Serializable,
Cloneable, or a certain type in a framework or library.
Marker interfaces are used to provide metadata about a class or to indicate that a class should be treated
differently by the compiler or runtime environment.
Examples:
java.io.Serializable: Classes that implement this interface can be serialized.
java.lang.Cloneable: Classes that implement this interface can be cloned using the clone() method.
Example of a marker interface:

Serializable Interface
Yes, the Serializable interface in Java is an example of a marker interface. A marker interface is an interface with no methods, and it is used to indicate a certain capability or behavior to the Java runtime.
The Serializable interface is part of the Java Serialization mechanism, and when a class implements Serializable,
it signals that instances of that class can be serialized.
Serialization is the process of converting an object into a byte stream, which can be saved to a file, sent over a
network, or stored in a database.
Implementing Serializable allows objects of the class to be easily converted into a format that can be reconstructed later.

abstract class Shape {
    // Abstract method (must be implemented by subclasses)
    public abstract double area();

    // Defined method with a concrete implementation
    public void display() {
        System.out.println("This is a shape.");
    }
}

class Circle extends Shape {
    private double radius;

    public Circle(double radius) {
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}

class Rectangle extends Shape {
    private double length;
    private double width;

    public Rectangle(double length, double width) {
        this.length = length;
        this.width = width;
    }

    @Override
    public double area() {
        return length * width;
    }
}

public class Main {
    public static void main(String[] args) {
        Circle circle = new Circle(5);
        circle.display(); // Output: This is a shape.
        System.out.println("Area of circle: " + circle.area()); // Output: Area of circle: 78.53981633974483

        Rectangle rectangle = new Rectangle(4, 6);
        rectangle.display(); // Output: This is a shape.
        System.out.println("Area of rectangle: " + rectangle.area()); // Output: Area of rectangle: 24.0
    }
}

import java.util.regex.Matcher;
import java.util.regex.Pattern;

public class RegularExpressionMatching {
    public boolean isMatch(String s, String p) {
        Pattern pattern = Pattern.compile(p);
        Matcher matcher = pattern.matcher(s);
        return matcher.matches();
    }

    public static void main(String[] args) {
        RegularExpressionMatching rem = new RegularExpressionMatching();
        String s = "aa";
        String p = "a*";
        System.out.println(rem.isMatch(s, p));  // Output: true
    }
}

We first compile the regular expression pattern p using Pattern.compile(p).
Then, we create a Matcher object by calling matcher(s) on the compiled pattern, where s is the input string.
We use the matches() method of the Matcher class to check if the entire input string matches the pattern.
Finally, we return the result of matcher.matches(), which indicates whether the input string matches the pattern.
This approach utilizes the built-in regular expression matching capabilities provided by the Java standard library,
making it concise and easy to use.

You obtain a Matcher object by calling the matcher() method on a Pattern object, passing in the input string.

super() in constructors:

When you create a subclass constructor, Java implicitly inserts a call to the superclass's no-argument
constructor (super()). If the superclass does not have a no-argument constructor and only has constructors with arguments, you must explicitly call one of those
constructors using super(arguments) in the subclass constructor.
If you don't explicitly call a superclass constructor using super(...), the compiler automatically inserts a call to super() as the first statement of the subclass constructor.
Explicit call to superclass constructor:

If you want to explicitly call a superclass constructor with specific arguments from a subclass constructor, you can use super(arguments). This must be the first statement in the subclass constructor.
super keyword in method overriding:

In a subclass, you can use the super keyword to explicitly call a method from the superclass with the same name as the overridden method in the subclass.
Inside a subclass method, super.methodName(...) calls the superclass's version of the method,
while methodName(...) calls the overridden version in the subclass.
Unlike constructors, there's no implicit call to the superclass method in overridden methods.
